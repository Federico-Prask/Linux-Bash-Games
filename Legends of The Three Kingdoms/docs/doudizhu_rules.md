## 补充（2026-10-05）：游戏开始时点的技能在斗地主同样发动

用户 2026-10-05 指出“所有游戏开始时点的技能都没有发动”是错的、必须改。核查发现**斗地主路径确实漏发**：
`initDoudizhuGame` 的正式建局也包在 `quietSetup` 里，而 `quietSetup` 会在 `onGameStart` 之前提前返回。
现已抽出 `GameEngine::runGameStartHooks()`，在斗地主正式建局并分发【飞扬】【跋扈】【共苦】之后调用，
因此【七星】【狂暴】【化身】【谋-明任】【势-妙略】【谋-结姻】【权谋】等“游戏开始时”技能在斗地主同样生效，
**蓄力技的初始点数也不再全为 0**（DIY钟会 1/5、势·钟会 4/4、谋·孟获 0/7、谋·公孙瓒 2/4、谋·诸葛瑾 1/3、势·邓艾 0/0）。
测试：`tests/test_game_start_rounds.cpp`。

## 一、已实现（本地口径）

| 环节 | 规则 | 实现位置 |
|---|---|---|
| 人数/阵营 | 3 人：1 地主 vs 2 农民 | `Roles::doudizhuIdentities`、`GameEngine::initDoudizhuGame` |
| 初始手牌 | 所有人 4 张（无底牌） | `setupGame`（4 张） |
| 地主优势 | 体力上限 +1、先手 | `Player` 构造（`DI_ZHU` +1）、`currentTurnIndex = 地主座位` |
| 亮将 | 所有人先亮 **3 个候选武将**（各自互相看不到：日志按座位输出，AI 候选不参与 AI 决策） | `GameEngine::initDoudizhuHeroPool` / `drawDoudizhuCandidate` / `logDoudizhuCandidates` |
| 抢地主（叫分） | 亮将后按座位 0→1→2 依次选“不叫 / 叫 N 分”（须高于当前最高分）；叫 3 分立即定地主；全不叫则座位 0 默认地主、底分按 1 | `GameEngine::runDoudizhuBidding` |
| 地主追加亮将 | 地主再亮 **2 个候选**（共 5 选 1） | `initDoudizhuGame` 阶段 4 |
| 选将 / 换将 | 每名玩家从自己的候选（地主 5、农民 3）中选 1；**所有亮出的位置都可换将 2 次**（人类输入 `r编号`）；候选间同一人物不重复；菜单预选武将作为人类首个候选 | `GameEngine::askDoudizhuDraftChoice` / `chooseDoudizhuHeroes` |
| 专属技能 | 地主【飞扬】【跋扈】、农民【共苦】（移动版原文，见文首） | `include/SkillsMode.h` / `src/SkillsMode.cpp`（`applyDoudizhuModeSkills`） |
| 结算 | 只按叫分底分：地主胜 地主 +2×底分、农民 −1×底分；农民胜反之；仅本地计分（明牌/加倍已删去） | `GameEngine::getDoudizhuScores`、`logDoudizhuSettlement` |

## 二·补、本地化说明

- **首叫位**：官方为随机/翻牌比点确定；本地固定从座位 0 开始（可复现，便于测试与复盘）。
- **AI 叫分**：启发式（武将体力上限 + 手牌【杀】数）。
- **无底牌**：按用户裁定（移动版无“底牌”说法），确定地主后不再发底牌。
- **“各自互相看不到”**：有真人参与时，亮将日志**只公布真人自己的候选**，其余座位显示“（对方候选不公开）”；全 AI 观战模式（演示/无真人）才全部展示。AI 的候选不参与其决策（AI 只在自己那份候选里取：普通场随机、至尊场按选将 AI 排名）。
- 结算只按叫分底分（本地计分），不影响牌局过程。

## 四、披露

- 本模式为**本地单机玩法**：不含联网匹配、资源（欢乐豆/金卡）、道具（换将卡/手气卡）与禁将方案。
- 番外（春天/炸弹翻倍等扑克计分）不适用：三国杀斗地主按击杀判定胜负，本地结算仅用叫分底分（明牌/加倍已按用户指示删去）。
