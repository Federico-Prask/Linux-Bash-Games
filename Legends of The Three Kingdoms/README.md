# thks (三国杀) 命令行版 - C++ 游戏核心引擎

[![CI](https://github.com/kzt111/thks/actions/workflows/ci.yml/badge.svg)](https://github.com/kzt111/thks/actions/workflows/ci.yml)

这是一个使用现代 **C++17** 编写的跨平台《三国杀》(thks) 命令行版游戏核心引擎 (Kernel/Engine)。

内核设计完全解耦，预留了**武将与技能拓展接口（Event Hooks）**，支持通过钩子扩展具体武将技能。当前登记 **126 名武将**：标准/风火林山/界限突破/一将成名/DIY 共 73 名，谋攻篇 37 名，势包/友/始计篇·智/神话再临·阴/身份武将共 16 名。**全部武将的技能描述已逐字替换为[三国杀移动版官网](https://www.sanguosha.cn/pc/hero-list.html)原文**，完整武将表格与按包技能清单见 **[hero.md](hero.md)**；核验过程与实现差异记录见 `docs/`。

---

## 🌟 核心特性

1. **跨平台支持 (Linux & Windows)**
   - 采用标准 C++17，无平台限定硬依赖。
   - 自动处理 Windows 控制台 UTF-8 编码 (`SetConsoleOutputCP(65001)`)，解决跨平台乱码问题。
   - 输出风格统一为**黑白纯文本**：不使用任何 ANSI 彩色转义序列，兼容重定向到文件 / 管道 / 不支持彩色的终端；
     强调一律使用【】、!、▲ 等文本标记。`Platform::displayWidth / padRight` 按 UTF-8 码点计算显示宽度（CJK/全角/emoji 记 2 列），保证任意环境下表格对齐。

2. **完整的三国杀基本牌与锦囊牌系统**
   - **基本牌**：杀（普通杀/火杀/雷杀）、闪、桃、酒。
   - **即时锦囊**：过河拆桥、顺手牵羊、决斗、南蛮入侵、万箭齐发、无中生有、桃园结义、无懈可击、借刀杀人、五谷丰登、火攻、铁索连环。
   - **延时锦囊**：乐不思蜀、闪电、兵粮寸断。
   - **装备牌**（效果均已实现，见 `src/Equipment.cpp`）：
     - 武器：诸葛连弩（杀无次数限制）、青釭剑（无视防具）、青龙偃月刀（被闪抵消后可再杀）、丈八蛇矛（两张手牌当杀，出牌阶段输入 `z`）、贯石斧（弃两张牌强制命中）、麒麟弓（命中时拆坐骑）、寒冰剑（防止伤害改为拆两张牌）、方天画戟（最后的手牌当杀可指定至多三个目标）
     - 防具：八卦阵、仁王盾、藤甲（普通杀 / 南蛮 / 万箭无效，火焰伤害 +1）、白银狮子（伤害至多 1 点，失去时回复 1 点体力）
     - 坐骑：-1马 / +1马
   - **虚拟牌**：支持"将 X 当 Y 使用或打出"（武圣、龙胆），日志中会显示 `【杀】(龙胆:[♥ 2 闪])` 这样的转化来源。

3. **完整的回合 6 阶段机制**
   - **准备阶段** -> **判定阶段** -> **摸牌阶段** -> **出牌阶段** -> **弃牌阶段** -> **结束阶段**。
   - 完善的距离计算（+1/-1马加减距离）、攻击范围计算、手牌上限计算。
   - 包含完整的响应机制（打【闪】响应【杀】、决斗/南蛮/万箭响应、濒死求【桃】/【酒】、胜负与阵亡赏罚等）。【无懈可击】按官方规则支持多张连锁反制（每张翻转生效状态、重新询问全体角色），AI 按阵营价值与连锁奇偶智能决策——只会让局面更优时出手，不会反制替自己挡刀的无懈。出牌 AI 会在有斩杀机会时先用【酒】（+1 伤害）、优先攻击可击杀目标；濒死时 AI 会用【酒】自救（官方文本第二句）；拆顺/延时锦囊选“可见牌量最多”的敌人、决斗挑手牌最少者。

4. **武将系统与武将选择**
   - 选将/图鉴的一级分类为 **标风火林山**（内含标准/风/火/林/山五个小包）、界限突破、一将成名、DIY包、谋攻篇、势包、始计篇、神话再临·阴；支持选小包或浏览整个大包，见 `HeroRegistry::packCategories`。同一人物的标准/界/神/DIY/谋/势/友版本（含诸葛亮、卧龙诸葛亮、谋·诸葛亮、友·诸葛亮）不会同场出现，指定冲突时后指定的座位重新抽取。
   - 支持 **2~8 人身份局**，身份构成对齐游卡官方规则表（`Roles::configFor`）：

     | 人数 | 主公 | 忠臣 | 反贼 | 内奸 |
     | --- | --- | --- | --- | --- |
     | 2 | 1 | 0 | 1 | 0 |
     | 3 | 1 | 0 | 1 | 1 |
     | 4 | 1 | 1 | 1 | 1 |
     | 5 | 1 | 1 | 2 | 1 |
     | 6 | 1 | 1 | 3 | 1 |
     | 7 | 1 | 2 | 3 | 1 |
     | 8 | 1 | 2 | 4 | 1 |

   - 开局可选择三种模式：
     1. **自选武将（＝点将）**：列出**全部**武将——至尊场的禁止池**只作用于随机池**（随机分配、选将框、亮将/换将候选，含玩家），**点将（显式指定）可以用全将**；可 `v编号` 查看技能详情、输入编号 **预选**（可反复更换、随时查看），最后输入 `y` 确认；该武将会成为你**选将候选的第 1 个**。
     2. **全部随机**：候选随机发出，仍进入选将（主公 5 选 1、其余 3 选 1）。
     3. **全 AI 观战**：所有座位由电脑操作（AI 也走选将），用于演示 / 回归测试。
   - **指定身份（用户 2026-10-05 裁定：玩家也可以指定或随机身份了）**：人数确定后可选“随机分配 / 主公 / 忠臣 / 反贼 / 内奸”；该人数局没有的身份（如 3 人局的忠臣）会提示并回退随机。指定后**主公仍先动**（`currentTurnIndex` 取主公座位，不再固定为 0）。
   - **身份场选将框（用户 2026-10-05 给出数量）**：**主公 10 个**（4 个“主公武将”＝拥有主公技的武将 + 6 个常规武将）、**忠臣 5 个**、**内奸 5 个**（各比反贼多 1 个作补偿）、**反贼 4 个**；斗地主维持地主 5 / 农民 3。**身份场每个框只能换将 1 次**（斗地主仍为每个位置 2 次）。主公**先选完并亮出武将与势力**，其余按座次选将（AI 据此“针对或辅助”）。
   - **框内取哪一个**：用户 2026-10-05 裁定——**普通场不论何种模式都是随机从选将框中选**；**至尊场**在排除**本模式禁止池**后由**选将 AI 排名预选，并有概率选排第二的**（**30%**，用户已确认；常量 `GameEngine::kSecondPickPercent`）。人类玩家仍可自由改选，预选项标 ★，可 `y` 直接接受；**每个座位的选将记录都附「预选: …」**（预选展示全部）。
   - **框内展示与对比**（用户 2026-10-05 指定）：每个候选一行 `武将名（包名） 势力 体力x/y ｜技能名（主公技标注）`；输入 **`d1,3`** 打开**对比面板**（势力/体力/称号/三档强度/本身份评分/技能全文/分档依据，最多并排 3 个），面板为插入式模态，返回后重印选将问题、不改游戏状态。
   - **主公框分两页**（用户 2026-10-05 选择）：第 1 页＝拥有主公技的“主公武将”（4 名）、第 2 页＝常规武将（6 名），`n`/`p` 翻页；**编号始终是全局编号**，★预选在另一页时会提示“在第 X 页：编号 N”。非主公框（4/5 个）不分页。
   - **真人选将不设超时**（用户 2026-10-05 选择“一直等”）：引擎没有任何计时器；唯一兜底是**输入源结束（EOF**，管道演示/脚本对局/CI**）**，此时采用 ★预选并明确记录“输入源已结束（未选择）：按 ★预选 采用 X”。AI 依据亮出的主公武将评分选将（不再随机）：忠臣偏好与主公**同势力**（可响应【护驾】【激将】【救援】【血裔】等主公技）与辅助型技能，反贼偏好**输出/控制**并避开主公技势力，内奸偏好**攻守兼备**（要能单挑），主公偏好**自带主公技 + 防御**。评分口径见 `src/AI.cpp::draftScore`，单测见 `tests/test_zhizun_draft.cpp`。
   - 选将流程在引擎内（`engine.setIdentityDraft(true)` + `initGame(...)`），`main.cpp` 只负责菜单与武将 ID，便于后续接入联机模式。**选将框的界面规格待用户补充**（见 `TODO.md` 第 1 项）。

5. **技能分类（依据游卡官方规则集）**
   - 三大种类（互斥，对应类继承第一层）：
     | 种类 | 基类 | 说明 |
     | --- | --- | --- |
     | 主动技 | `ActiveSkill` | 由玩家主动发动（含"将 X 当 Y 使用或打出"的视为转化） |
     | 触发技 | `TriggerSkill` | 具有发动时机，满足条件时发动 |
     | 状态技 | `StateSkill` | 无发动时机、持续生效；不自动等同于移动版“持恒技” |
   - 标签（可叠加）：锁定技 / 限定技 / 觉醒技 / 主公技 / 转换技 / 持恒技。持恒技与状态技类别分离；本引擎按持恒标签保留其抗失效、不可移除规则。
   - 继承层次固定为两层：`Skill` → 种类基类 → 具体技能类，例如 `Skill → StateSkill → MaShuSkill`。

6. **技能事件钩子 (`Skill`)**
   - `onGameStart` / `onTurnStart` / `onRoundStart` / `onPhaseStart` / `onPhaseEnd`：阶段与轮次流程（支持跳过阶段；`onTurnStart`/`onRoundStart`/`onPhaseEnd` 会广播给所有存活角色，支持"一名玩家的出牌阶段结束时"类触发）
   - `onDrawCards` / `onCalculateHandLimit` / `onCalculateDistance` / `onCalculateShaLimit` / `onCheckShaTarget`：数值与规则修正（马术、咆哮、界武圣、界烈弓）
   - `convertCard`：卡牌转化（武圣、龙胆）
   - `onShaTargeted` / `onShaFinished`：【杀】指定目标后 / 结算后（铁骑、烈弓、替身）
   - `onTakeDamage` / `onDealDamage` / `onClaimDamageCard` / `onAfterDamage` / `onAfterDealDamage` / `onDying`：伤害与濒死（伤害钩子带 `cause` 伤害牌；奸雄可认领之；权计、界义绝、权谋、裸衣）
   - `onCalculateRecover` / `onEquipmentLost` / `onUseCard` / `onHandEmpty`：回复量修正（救援）、失去装备后（枭姬）、使用非延时锦囊时（集智）、失去最后一张手牌后（连营）
   - `onBeforeJudge` / `onAfterJudge`：判定牌生效前替换（鬼才）/ 生效后获得（天妒）
   - `onCheckCardTarget` / `onCalculateResponseCount` / `onNeedResponseCard`：目标合法性（空城/谦逊）、响应张数修正（无双）、同势力借牌响应（激将/护驾）
   - `onCardUsedOutsideTurn`：回合外使用或打出手牌（涯角）
   - `canActivate` / `activate` / `aiShouldActivate`：主动技的发动条件、效果与 AI 决策（义绝、排异；势/友包主动技也有门控，如【势-肆恣】需有蓄力点、【势-缔盟】需两人手牌相近、【势-逆固】需两张不同花色才发动）

## 武将系统要点

- **收录范围**：标准包、风/火/林/山包（含神将）、界限突破、一将成名、DIY包、谋攻篇、势包、友、始计篇·智、神话再临·阴、身份武将（花鬘）、许攸、骆统等，共 126 名；完整名单与技能原文见 [hero.md](hero.md)。
- **同名技能按武将版本分别实现**：普通钟会与界钟会的【自立】文字相同、复用同一技能；【权计】触发时机不同，分版本实现；DIY 钟会的【权谋】【权计】【自立】及觉醒所得【排异】由专属实现处理，不套用普通/界钟会技能。势包内同名技能（如两版【屯田】）同样分开。
- **描述口径**：技能描述逐字照录三国杀移动版官网（含官网自带的技能名前缀与重复段落）；官网原文存在明显错字/漏字时照录，并在描述内以“（官网原文如此）”标注，实现按正确规则执行。逐字比对由 `tests/test_official_audit.cpp` 与 `tests/test_mou_pack.cpp` 覆盖。
- 图鉴可查看目前登记的技能和提示；对局中输入 `m` 可打开记牌器（按基本牌/锦囊牌/装备牌查看牌堆剩余实体牌），输入 `t`/`v` 打开图鉴。两者均为暂停式只读面板，退出后回到原提示。

## ⚠️ 已知限制与未完成项

- **斗地主**：3 人局；所有人先**亮 3 个候选武将**（各自互相看不到）→ **抢地主**（叫分）→ 地主再亮 2 个候选 → **选将**（地主 5 选 1、农民 3 选 1；所有亮出的位置**可换将 2 次**）→ **开局换牌**（每人至多 7 次，见下）→ 对局 → 本地结算（只按叫分底分，不涉及任何资源）。**专属技能已实现**：地主【飞扬】（判定阶段弃 2 张牌并移除判定区一张牌，每回合限 1 次）、【跋扈】（锁定技：准备阶段摸 1 张、出牌阶段多使用 1 张【杀】）；农民【共苦】（队友阵亡时回复 1 点体力或摸 2 张牌）。所有人初始 4 张手牌、无底牌（用户裁定）；**选将 AI 已改为评分选将（不再随机）**：地主按“1 打 2 自给自足”（输出/防御/控制）、农民按“配合队友”（辅助/输出）加权，叠加斗地主强度档（`HeroTier`，地主篇/农民篇榜单）。规则与来源见 `docs/doudizhu_rules.md`。
- **至尊场（用户 2026-10-05 / 2026-10-06 两次裁定，已实现）**：**身份场与斗地主各有一张独立的禁止池，门槛抬高到每池 30 名以上，两张名单可以不一样，且只在至尊场生效**（普通场仍是全部 124 名武将）。
  - 身份场禁止池 **34 名**：军争星级 **≤4 星**，或 5 星但资料有明确负面评述（白板/脱离节奏/不入流/自爆/难评…）。
  - 斗地主禁止池 **32 名**：**地主档弱**（该包已点名可用者而未入榜）**且农民档没有“明确可用”评级**（农民一/二/三级、及格线、可用、有奇效、防兵乐、神级农民等）；两池并集 49 名。
  - **生效范围＝随机池**：随机分配、身份场选将框、斗地主亮将/换将候选（**含玩家的随机候选与换将**）都不会出现本模式的禁将；**点将（显式指定武将，如 CLI 自选武将 / `initGame` 传入的 heroIds）可以用全将**——弱将入场时日志会打印「至尊场·点将」注明原因。
  - 分档数据、两张名单与逐条依据见 **`docs/zhizun_field_rules.md`**；代码表在 `src/HeroTier.cpp`（`isBannedInZhizun(id, Mode)`，由 `tools/gen_hero_tier.py` 与文档同步生成）。
  - **已知缺口（如实披露）**：谋攻篇 37 名、势包 10 名、友·诸葛亮、花鬘缺公开分模式统计，一律记「中档保留」（不移除）；官方游戏内 6 项评分（主公/忠臣/反贼/内奸/地主/农民）为图片表未取到数值，若日后拿到应以其覆盖本表。
  - 官方《三国杀移动版》的“至尊场”实为高门槛房间（等级/胜率门槛），并不移除弱将；本项目按用户裁定实现为“移除弱将”的场次开关，两者不是一回事。
- **身份场新机制（用户 2026-10-05 提供规则，已实现）**：详见 **`docs/identity_field_rules.md`**。
  - **内奸【择途】**：场上**存活角色 > 4** 时、**每局限一次**，**在自己的回合内任意时刻**主动发动（回合开始 / 每个阶段开始 / 出牌阶段主动技菜单 / 自己回合内有角色阵亡后）；发动时**明置自己的身份牌**（此后该身份对人类公开），并立即二选一——**侍奉明主**（身份牌直接变为忠臣，胜利条件同步变为主忠方）／**自立为主**（成为独立的**野心家**，获得斗地主版的【飞扬】【跋扈】——用户明确“还是之前说的技能，不用改”；**即使主公阵亡也不立即失败**，目标是成为唯一幸存者）。
  - **主公【立储】**：**第一轮的任意角色结束阶段**可**明选**一名角色为**储君**（太子，公开标记）；主公阵亡时**储君若为忠臣则继位成为新的主公**（继位在胜负判定之前处理，延续主忠方）。非忠臣储君不能继位。

### 开局换牌（用户 2026-10-06 裁定，已实现）

- 规则原文：「每个人可以换七次牌（初始手牌，属于游戏开始前，此时任何技能都未发动）」；经追问确认**所有座位（含 AI）都能换**。
- 时机：建局时**发完 4 张初始手牌之后、任何技能钩子（`onGameStart`、主公技授予）之前**——换牌不发动任何技能、不计入弃牌相关钩子。
- 次数：每人**至多 7 次**（`GameEngine::setMulliganMaxSwaps`，默认 7）；每次换 1 张，换出的牌置于牌堆底、随即补 1 张（牌堆空则回滚原牌）。
- 真人：逐个座位提示「【换牌】更换初始手牌（剩余 N 次…）」，输入编号换牌、`0` 结束；AI：只换掉 `AIController::cardValue < 4` 的低价值牌（杀/闪/桃等基本牌保留）。
- 顺序：从当前回合角色起按座位（身份场＝主公，斗地主＝地主）。日志只报真人的具体牌与 AI 的换牌次数。
- 开关：`setMulliganEnabled`（**建局默认开启**，全 AI 观战同样换牌；显式 `false` 可在建局时关闭、不被默认值覆盖）、`isMulliganEnabled`、`getMulliganMaxSwaps`、`mulliganSwapsOf(seat)`；单测见 `tests/test_mulligan.cpp`（5 项）。

### 游戏内操作

- **选将界面**（标风火林山含三级）：先按 **扩展包分类** 选择（标风火林山〔下一层再选标准/风/火/林/山〕 / 界限突破 / 一将成名 / DIY包 / 谋攻篇 / 势包 / 始计篇 / 神话再临·阴 / 全部武将），再在分类内 `编号` 预选武将 → `v编号` 查看技能详情 → `y` 确认；`r` 从当前分类随机一名；`t` 打开图鉴；`0` 返回上一级（包分类页按 `0` 退出）。
- **出牌阶段**：输入手牌编号使用牌；`s编号` 发动主动技（如义绝、排异、权计）；`z` 发动丈八蛇矛（两张手牌当【杀】）；`v`/`t` 打开图鉴（先看自己的武将，可再浏览全部）；`m` 打开记牌器；`0` 结束出牌阶段。
- **图鉴与记牌器**：图鉴提供武将（含技能说明）与卡牌规则浏览；对局中在**任何需要输入时**按 `t`/`v` 打开图鉴、按 `m` 打开记牌器。两者均暂停对局、退出后**恢复状态并重新输出原问题**；记牌器按类别列出当前摸牌堆内各实体牌的花色、点数与剩余数量，支持从记牌器直接进入图鉴。选将界面的 `v编号` 预览不受影响。
- **观察局势**：对局中在**任何需要输入时**按 `c`/`q`/`g`/`l` 打开（`0` 返回，同样会重新输出原问题）。内容包含：① 场上的牌——各角色装备区、判定区（延时锦囊）与武将牌上的牌；② 公开状态——体力/身份/手牌数、技能状态（限定技/觉醒技“已用/已发动/已觉醒”等）与蓄力点（`蓄力 X/Y`）、护甲等公开标记；③ 私有状态——**自己的手牌**（仅本人可见，AI 手牌不外显）。
  - **转化类技能（"将 X 当 Y 使用或打出"）**：出牌阶段可以 `s编号` 直接发动该技能——引擎遍历 `CardSubType` 全表调用技能的 `convertCards`，由技能筛出**此刻适合使用**的候选牌（闪/无懈不能主动使用、满血不能用桃、杀与各类锦囊要有合法目标，均由 `GameEngine::canPlayCardNow` 过滤）；
    也可以先选一张手牌，引擎列出该牌经各技能的全部可转化结果，由你选择"按原牌使用 / 发动【技能】当作【某牌】使用"——**不选技能就不会发生转化**（仅【武神】【无谋】这类锁定技在原牌被禁止直接使用时不再重复询问）。
    响应窗口（被【杀】、南蛮/万箭、决斗、求桃、无懈可击）的候选牌里会直接列出 `【闪】(龙胆:[♦ 8 杀])` 之类的转化项。

主忠方清场后仍需清掉野心家 / 洗白后随主忠方获胜）、【立储】仅第一轮且仅主公、储君继位与非忠臣不继位、继位先于胜负判定；
并含 4 条**死循环回归**（谋·张飞【协击】、谋·诸葛亮【看破】——实机 seed=131 / seed=143 曾挂起）；
另有选将框展示与交互专测：框内展示 势力/体力x/y/技能名、主公框前 4 个必为主公武将、`d1,2` 对比面板为插入式模态且不改状态、
每个座位的预选都进日志、【择途】只能在自己回合内发动、发动时明置身份牌（`isIdentityPublic` 转为公开）、
野心家拿到的【飞扬】【跋扈】与斗地主地主版**描述完全一致**。

**持续集成（CI）**：仓库配置了 GitHub Actions（`.github/workflows/ci.yml`），每次 push / PR 自动执行——
Linux (g++)、macOS (clang)、Windows (MSYS2 MinGW) 编译 + `make test`，Windows (MSVC + CMake) 编译 + `ctest`，
另跑 ASan/UBSan 测试与全 AI 冒烟对局（`THKS_SEED` 固定种子），无需手动记得跑测试。

### 可选环境变量

| 变量 | 作用 |
| --- | --- |
| `THKS_SEED` | 指定随机种子（洗牌、身份、随机选将），用于复现对局 |
| `THKS_AI_DELAY` | 电脑行动间隔毫秒数（默认 300，设为 0 可加速；全 AI 观战模式默认 0） |
| `THKS_SEED`（测试） | 测试进程若未设置该变量，`tests/test_main.cpp` 会统一注入固定种子 **20261005**，保证整套测试可复现（大量既有测试没有显式 `setSeed`，此前身份洗牌与牌堆顺序会随运行时刻变化而偶发失败） |
| `THKS_AI_TRACE` | 设为 1 时把 AI 决策跟踪打到 **stderr**（出牌迭代、主循环轮次、轮次开始广播、【择途】评估输入与结论），用于排查挂起/调参；不影响游戏输出与测试 |

示例（全 AI 观战、固定种子）。菜单顺序为 **玩法 → 场次 → 人数 → 身份 → 武将分配**（斗地主为 玩法 → 场次 → 分配）：

```bash
printf '1\n1\n5\n1\n3\n' | THKS_SEED=13 ./thks   # 身份场 5 人、普通场、身份随机、全 AI 观战
printf '1\n2\n5\n1\n3\n' | THKS_SEED=14 ./thks   # 至尊场（移除弱将）+ 选将，全 AI 观战
printf '1\n2\n5\n4\n2\n' | THKS_SEED=16 ./thks   # 至尊场、指定反贼、全部随机（进入选将后需交互出牌）
printf '2\n2\n3\n'           | THKS_SEED=15 ./thks   # 斗地主、至尊场、全 AI 观战
```

## 🧩 架构解耦（v2 重构）

引擎的"输出 / 交互 / 身份规则"已从 `GameEngine` 中拆分为可替换组件：

| 模块 | 职责 | 替换场景 |
| --- | --- | --- |
| `Logger` | 所有游戏文本经它输出（黑白纯文本）；`engine.setLogger()` 可注入任意 `std::ostream` | 接 GUI / 联机 / 测试捕获 |
| `Interaction` | `askConfirm / askChooseCard / askChoosePlayer / askChooseOption`，AI 直接取预选答案、人类读控制台 | 接图形界面或远端输入 |
| `Roles` | 2~8 人官方身份配置表、随机入座、胜负判定 | 扩展新人数/身份玩法 |
| `HeroTier` | 武将强度分档（身份场/斗地主）与至尊场弱将移除名单；选将 AI 与场次过滤共用同一张表 | 拿到官方 6 项评分后整表替换（`tools/gen_hero_tier.py`） |

测试即受益于此：`tests/test_helpers.h` 的 `captureLog()` 把日志捕获到字符串流做断言。

## ➕ 如何新增武将

1. 在 `include/Skills.h` / `src/Skills.cpp`（或 `include/SkillsStd.h` / `src/SkillsStd.cpp`）中派生对应种类的基类（`ActiveSkill` / `TriggerSkill` / `StateSkill`）实现技能，按需覆盖事件钩子，并在构造函数中标注标签（如 `SkillTag::LOCK`）。
2. 在 `src/HeroRegistry.cpp` 的登记表中新增一行（id、名称、称号、扩展包、势力、性别、体力、技能列表）。新扩展包可在 `HeroRegistry::packCategories()` 中归入选将分类（标风火林山 / 界限突破 / 一将成名 / DIY包）。
3. 重新编译即可，选将界面会自动按扩展包分组显示新武将。
